🛠️ Habilidades — los verbos conquistados

La unidad de capacidad del OS. Empieza a mano, destila con reverse meta-prompting, itera para siempre — y aprende cuándo una skill debería convertirse en un script.

Qué es:

Haz la tarea a mano primero —a veces, pasando una hora escribiendo todo tu razonamiento— y solo entonces captura los pasos en una skill.

Por qué aprender:

Una skill de algo que nunca hiciste a mano queda genérica y falla. Hacerlo manualmente primero garantiza que la receta refleje la realidad.

Conceptos clave:

Primero el manual · preparación del contexto · capturar el proceso.

Qué es:

Pedirle a la IA: "con base en esta conversación, destila el criterio exacto y materialízalo en un slash command que siempre pueda consultar".

Por qué aprender:

Es escribir la receta después de cocinar: nunca más rehacer el mismo briefing de una hora.

Conceptos clave:

Destilar la conversación · comando slash · receta después del plato.

Qué es:

Lanzas una V1 y sigues ajustándola. El autor tiene una skill que perfecciona casi todos los días desde hace seis meses.

Por qué aprender:

Tratar una skill como «lista» hace que se deteriore. El ciclo está vivo: usar, observar, ajustar.

Conceptos clave:

Ship a V1 · iteración continua · ∞.

Qué es:

Al final de la sesión, pregunta "¿cómo deberíamos ajustar la skill?" y ofrece una rúbrica para decidir cuándo cambiar algo (o no).

Por qué aprender:

La rúbrica evita ajustes impulsivos: la skill solo cambia cuando el criterio lo justifica.

Conceptos clave:

Post-mortem · rúbrica · cambio con criterio.

Qué es:

Si una skill se ejecuta al 100% de forma autónoma (entrada→salida fijas), quizá debería ser un script/cron determinístico escrito por la IA.

Por qué aprender:

Un script consume menos tokens y contexto, y no hace falta cargarlo en la ventana en cada sesión.

Conceptos clave:

100% autónoma · cron · ahorro de contexto.

Qué es:

La gente las subutiliza, acumula o se cree lista y crea demasiadas skills que quedan obsoletas, y skills para algo que nunca se ha hecho a mano.

Por qué aprender:

Empezar con UNA skill (la que más repites) evita que la carpeta se llene de recetas muertas.

Conceptos clave:

Una skill primero · sin acumular · sin skills fantasma.

Qué es:

Un prompt listo que le pide a Claude Code que destile la conversación actual en un /slash command que acepta un argumento.

Por qué aprender:

Es el ejercicio práctico: sales del módulo con tu primera skill materializada.

Conceptos clave:

Copy-run · argumento · SOP en secuencia.

Qué es:

Las partes de un SKILL.md: nombre, cuándo usarla (trigger), paso a paso (SOP) y cómo verificar.

Por qué aprender:

Conocer la anatomía te permite leer, depurar y mejorar cualquier skill, propia o ajena.

Conceptos clave:

Nombre · activador · SOP · verificación de finalización.

🔌 Herramientas y conexiones — los cables hacia afuera

¿Skill, CLI, API o solo MCP? Cómo envolver una API en una CLI propia — y el truco de seguridad que lo cambia todo: la CLI de solo lectura.

Qué es:

Antes de conectar cualquier herramienta, audita: ¿ofrece skill, CLI, API o solo MCP? La respuesta define el camino.

Por qué aprender:

Elegir mal cuesta mantenimiento y contexto. La pregunta filtra antes de que inviertas esfuerzo.

Conceptos clave:

Auditar la herramienta · 4 conectores · elección consciente.

Qué es:

Con el tiempo, el MCP tiende a ser menos relevante. Solo vale la pena cuando la herramienta ofrece MCP, pero no API.

Por qué aprender:

Dejas de instalar MCP por reflejo y prefieres una skill o una CLI cuando hay una API.

Conceptos clave:

MCP en declive · solo MCP es una excepción · prefiere la API.

Qué es:

Puedes pedirle a Claude Code: "convierte esta API en una CLI personalizada con estas funciones principales".

Por qué aprender:

Cuando el trabajo implica mucho uso de la línea de comandos, una CLI propia es más ligera que llamar a la API directamente.

Conceptos clave:

Wrap de la API · funciones elegidas · control remoto ligero.

Qué es:

Diseña la CLI de modo que físicamente no tenga acceso de escritura: solo lee datos, nunca escribe en la base de datos.

Por qué aprender:

Elimina el riesgo de un POST destruir datos accidentalmente cuando estás muy avanzado en la ventana de contexto.

Conceptos clave:

Read-only · sin write · tripwire físico.

Qué es:

Cada conexión o CLI que agregas es una pieza nueva que debes mantener. Agrégala con intención, no por reflejo.

Por qué aprender:

Demasiada infraestructura causa más problemas de los que resuelve. A veces la skill lista resuelve el problema sin que tengas que construir nada.

Conceptos clave:

Costo de mantenimiento · intencionalidad · menos es más.

Qué es:

Supabase CLI (base de datos de Health OS), Obsidian CLI (segundo cerebro) y la skill Appify (scraping): lista, sin CLI propia.

Por qué aprender:

Muestran cuándo crear tu propia infraestructura y cuándo una skill de terceros ya hace el trabajo.

Conceptos clave:

CLI cuando la necesito · skill cuando basta · combinar.

Qué es:

Un prompt listo que pide transformar una API en una CLI solo lectura, con las funciones que enumeras.

Por qué aprender:

Es el ejercicio práctico: sales con una CLI segura para tu herramienta favorita.

Conceptos clave:

Copy-run · read-only · funciones explícitas.

Qué es:

Si una skill lista (p. ej., Appify) ya hace el trabajo, no te mates manteniendo una CLI propia solo por orgullo.

Por qué aprender:

Reconocer cuándo parar es tan valioso como saber construir. Cada pieza extra es una deuda.

Conceptos clave:

Con la skill lista basta · no reinventar · deuda de infraestructura.

🤖 Agentes — roles con criterio

La última capa, no la primera. Skill es un verbo; agente es el chef que elige skills, en orden, con una puerta de revisión antes de que salga algo.

Qué es:

Skill = un verbo repetible. Agente = un trabajador especialista que orquesta varias skills con criterio.

Por qué aprender:

Confundir ambos te lleva a crear un agente cuando bastaba con una skill: caro y frágil.

Conceptos clave:

Verbo vs. trabajador · criterio · orquesta skills.

Qué es:

Todo agente que produce algo que se envía al exterior pasa por un review gate: un punto donde tú (u otro agente) revisas antes del envío.

Por qué aprender:

Es lo que separa a un agente confiable de uno que envía tonterías al cliente/contador.

Conceptos clave:

Review gate · humano en el loop · verificación antes del envío.

Qué es:

Promueve a agente solo una rutina que ya ejecutas a mano hoy, con skills existentes para que la orqueste.

Por qué aprender:

Un agente sin skills debajo ni una rutina real se vuelve teatro: parece poderoso, no entrega.

Conceptos clave:

Rutina real · skills primero · requisito previo.

Qué es:

Una tarea puntual (auditar cientos de archivos) quizá sea un workflow dinámico, no un agente fijo. ¿Necesitas más fuerza? Lanza subagentes descartables.

Por qué aprender:

No todo trabajo merece un "empleado" permanente. Elegir la forma adecuada ahorra.

Conceptos clave:

Agente fijo · workflow · subagentes throwaway.

Qué es:

En Freedom OS: un agente de respuestas (revisa Gmail y redacta respuestas con los documentos adecuados) y un agente de investigación profunda (monitorea cambios en las leyes de pasaporte).

Por qué aprender:

Los casos reales muestran agentes como «empleados» de un dominio, cada uno con un trabajo claro.

Conceptos clave:

Agente de respuesta · investigación profunda · OS vivo.

Qué es:

Un agente revisor escéptico (abogado del diablo) que «te insulta antes que el contador/cliente»: revisa el trabajo antes de que salga.

Por qué aprender:

Reduce las idas y vueltas: tu propio OS te «roasted» antes de que el error llegue a quien importa.

Conceptos clave:

Revisor escéptico · abogado del diablo · gate adversarial.

Qué es:

A medida que los modelos se vuelven más inteligentes, el mismo agente necesita menos instrucciones, o el agente deja de ser necesario porque el harness ya lo hace de forma nativa.

Por qué aprender:

Te hace revisar los agentes periódicamente en vez de acumularlos para siempre.

Conceptos clave:

Menos instrucciones · el agente desaparece · revisión periódica.

Qué es:

Un esqueleto listo para copiar de AGENT.md: función, skills que orquesta, orden, review gate y límites.

Por qué aprender:

Es el ejercicio práctico: sales con tu primer agente esbozado y listo para completar.

Conceptos clave:

Copy-run · rol + skills + gate · límites.
