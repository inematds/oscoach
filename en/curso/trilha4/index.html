⚙️ Install and understand the OS Coach

Copy the skill into a folder, learn the 6 commands, the memory.md, the 8 golden rules, the guards, and the loop that holds everything together.

What is:

Installing means copying the folder os-coach for ~/.claude/skills/. One command, no build, no dependencies.

Why learn:

It’s the only prerequisite. Without it, the /os-coach doesn’t exist on your machine.

Key concepts:

cp -r · skills folder · zero dependencies.

What is:

A copilot that does the technical work for you. It asks, you decide; it creates the files.

Why learn:

You don’t need to know how to code — assume you’ve never opened a terminal.

Key concepts:

Does it for you · one layer at a time · you decide.

What is:

Six verbs: start (begins), next (next layer), layer (skip to one), status (map), audit (scores), help (explains).

Why learn:

It’s the entire keyboard you’ll use on this learning path. Memorizing these six is enough.

Key concepts:

start · next · layer · status · audit · help.

What is:

A file that stores the goal, current layer, and decisions. Read first and updated last on every turn.

Why learn:

It’s what lets you stop halfway and come back days later without losing your place.

Key concepts:

Persistent state · resume later · always up to date.

What is:

Talk like a human, one step at a time, the skill does the building, never generic, always persistent, end the turn the same way, no em dashes, protect sensitive information.

Why learn:

Knowing the rules tells you what to expect—and when the coach is going off script.

Key concepts:

8 rules · grounded in reality · protect data.

What is:

Checks that prevent errors: run next without having start, overwrite an OS, invent a 7th layer.

Why learn:

Understanding the guards explains why the coach sometimes stops and asks instead of acting.

Key concepts:

No memory → ask to start · don't overwrite · don't make things up.

What is:

The engine: ask, build, persist, advance, audit. All reading and writing to the same memory.md.

Why learn:

It’s the rhythm of the entire learning path. Your first hands-on action: run /os-coach help.

Key concepts:

Ask · Build · Persist · Next · Audit.

🎯 start — objective + Identity

The first command. You state your goal, answer 2-3 questions, and the coach writes the CLAUDE.md — the lean soul of your OS.

What is:

The command that creates a new OS in the current folder and captures your goal in your own words.

Why learn:

Everything afterward is anchored to that goal—starting well prevents a generic OS.

Key concepts:

start · goal in your own words · folder = OS.

What is:

Who is the OS for, what would you like to simply ask it to do, and one thing it should always do and one it should never do.

Why learn:

Three short answers already give you almost all of the Identity. It's fast by design.

Key concepts:

Who it’s for · what to ask · always / never.

What is:

The coach checks what you’ve already said and reuses it. It never asks “who’s this for?” twice.

Why learn:

Shows that the goal + the start answers already cover almost all of Identity.

Key concepts:

Reuse · no repetition · only the question that’s missing.

What is:

A short file: who the OS is, whom it serves, the goal, 2-3 defaults, and 2-3 hard refusals.

Why learn:

It’s the first file the OS reads. Lean is better — cut until it hurts.

Key concepts:

< 30 lines · defaults · hard refusals.

What is:

If you mark a field as private, the coach records an identifier (“Client A”), never the real value.

Why learn:

Protects names, emails, and values from the first layer, without you having to police them.

Key concepts:

Handle · real value outside · no leaks.

What is:

A stranger reads the CLAUDE.md and correctly describes what the OS is for and one thing it refuses.

Why learn:

It’s the green light for Identity. Pass the test, and the layer is solid.

Key concepts:

Stranger test · solid · one clear refusal.

What is:

Your first real build: run the start with your goal, inside a new folder.

Why learn:

Move from concept to creating the first files: memory.md + CLAUDE.md.

Key concepts:

Hands-on · concrete goal · verify the files.

🗂️ next — Substrate

The largest and most skipped layer. The next open the Substrate: sources.md + compendium.md, de-identification and the multi-part done check.

What is:

O next read the memory.md and opens the next unfinished layer. After Identity, you move to Substrate.

Why learn:

It’s the command you repeat most. It follows the right order for you.

Key concepts:

next · build order · one layer at a time.

What is:

sources.md list where the material comes from; compendium.md is the distilled reference the OS actually reads.

Why learn:

These are the two canonical files. The audit looks for them by these names.

Key concepts:

sources · compendium · distilled > raw pile.

What is:

When distilling, names and values marked as sensitive become handles. Never create a file that says “I excluded X” and lists X.

Why learn:

The substrate is where accidental leaks are most likely—it’s where real data enters.

Key concepts:

Stable handle · no contradictions · ask first.

What is:

If you already have the material, the coach offers to gather and distill it on the spot; otherwise, it notes what’s missing in the memory.md.

Why learn:

You make progress even without everything in hand — the gap is recorded, not forgotten.

Key concepts:

Gather · distill · record what’s missing.

What is:

If the tough question has two parts (“what’s winning AND what’s already overdue”) and a piece of data is missing, the layer is in progress, not solid.

Why learn:

The coach is honest about what it still can’t answer—and tells you what data would resolve it.

Key concepts:

Multi-part · honesty · which input is missing.

What is:

Throw everything in raw into compendium.md. A small, clean compendium beats a giant, messy one.

Why learn:

Dirty substrate clogs context. Distilling is the real work of this layer.

Key concepts:

Distill > dump · small and clean.

What is:

Run /os-coach next in the same folder for the coach to open and build the Substrate.

Why learn:

Create the folder substrate/ with the canonical files, anchored to your goal.

Key concepts:

next · substrate/ · check the compendium.

🚧 next — Rules

The OS guardrails: always.md + never.md. The worst mistake becomes a never, plus an automatic reflex and the private-data rule.

What is:

The folder rules/ with always.md (what to always follow) and never.md (hard stops).

Why learn:

Written rules become reliable behavior — they don’t depend on you remembering.

Key concepts:

always · never · rules/.

What is:

"What’s the worst mistake this OS could make?" The answer becomes a clear never-rule.

Why learn:

Turns your biggest fear into a black-and-white fence.

Key concepts:

Worst mistake · concrete never-rule · black-and-white.

What is:

A hook is a locked door: a reminder, check, or backup that happens every time without anyone having to remember.

Why learn:

A rule is a “no entry” sign; a hook is stronger because it can’t be ignored.

Key concepts:

Hook > rule · automatic · locked door.

What is:

If there’s private data in the folder, add a never rule: “never upload or share this folder publicly.”

Why learn:

A leak can't be undone. This rule is usually the audit's #1 action.

Key concepts:

Public never · irreversible · high priority.

What is:

"Be careful" isn’t a rule. "Never mix numbers from two clients" is — you can test it.

Why learn:

A vague rule protects nothing. Concrete and testable is the default.

Key concepts:

Concrete · testable · no vagueness.

What is:

The layer is ready when the worst mistake has become a clear never-rule and at least one automatic reflex has been identified.

Why learn:

Sets an objective target for “Rules ready” instead of an endless list.

Key concepts:

Never written · 1 reflex · clear target.

What is:

Run /os-coach next again so the coach can open the Rules and write always.md + never.md.

Why learn:

Reinforces that next is the same command for every layer—the order is automatic.

Key concepts:

next · rules/ · same verb.

🧩 Skills → Tools → Agents

The three capability layers, in order. The first skill (the one you repeat most), the tools.md read-only and the first agent — only after the skills.

What is:

A folder skills/ with ONE SKILL.md: when to use it, the steps, and how to tell whether it worked well.

Why learn:

Start with the task you repeat most often. One good skill beats ten half-finished ones.

Key concepts:

One skill · the most repeated · SKILL.md.

What is:

You cook by feel a few times, then write down the recipe. A skill is a verb you earn.

Why learn:

Writing a skill for something you've never done by hand produces the wrong recipe.

Key concepts:

Manual first · capture later · earned verb.

What is:

One tools.md that lists every connection, what it's for, and whether it's read-only or write-enabled. Never keep secrets in the folder.

Why learn:

The read-only pattern is the security hack: the OS looks, but doesn't touch.

Key concepts:

Read-only · no secrets · only where writing is needed.

What is:

One AGENT.md for the first role worth promoting: what it does, which skills it orchestrates, and the review gate before it goes out.

Why learn:

Only promote a routine to an agent if you already do it manually today — and there are skills for it to orchestrate.

Key concepts:

AGENT.md · orchestrates skills · review gate.

What is:

Skills before Tools before Agents. The coach blocks building an agent without skills for it to orchestrate.

Why learn:

Going to Agents too early is the most common mistake. The order protects you from it.

Key concepts:

Order · skills first · agents last.

What is:

If a layer doesn’t yet apply to your goal, the coach marks it not started with a one-line reason and moves on.

Why learn:

Honesty is better than inventing work. You're not pushed toward an unnecessary agent.

Key concepts:

not started · reason in 1 line · no busywork.

What is:

Three next in sequence cover Skills, Tools, and Agents—each when it's ready.

Why learn:

You build the three capability layers of your OS, in the safe order.

Key concepts:

next ×3 · skills/ · tools.md · agents/.

📊 audit — score against the objective

The command that closes the loop. Scores the 6 layers, writes the OS-AUDIT.md, gives you the 3 highest-leverage moves and wraps up with the guided photographer example.

What is:

Read the memory.md, opens the actual folder and scores each layer against your goal.

Why learn:

It’s the command that honestly tells you where your OS really stands.

Key concepts:

audit · against the objective · scans the folder.

What is:

A file with the scorecard, the next 3 steps, and what already works—written for you to keep.

Why learn:

Because it can be saved, it must never contain leaked sensitive data.

Key concepts:

Scorecard · savable · no leaks.

What is:

Missing (doesn't exist), Started (thin), Solid (passes the done check), Compounding (improves on its own over time).

Why learn:

It's the honest yardstick. Most new OSs are Missing or Started — and that's okay.

Key concepts:

4 levels · honest · start small.

What is:

Instead of a huge list, three actions in order, each tied to the goal and a real file.

Why learn:

Focus. You leave the audit knowing exactly what to do next.

Key concepts:

3 moves · by leverage · real file.

What is:

Every line in the audit must fail if pasted into a stranger's audit. It cites real goals, gaps, and file names.

Why learn:

A generic audit is a failed audit. This test ensures advice that works for YOU.

Key concepts:

Specific · cites files · no boilerplate.

What is:

Urgent/irreversible hard rules come first; otherwise, a substrate gap takes priority; skills only with substrate; agents last.

Why learn:

Explains why the audit sometimes ignores the “fun part” and tells you to fix the foundation.

Key concepts:

Precedence · foundation before capability · agents last.

What is:

The audit rewrites the status block in the memory.md and note the date — then the next next already starts from there.

Why learn:

Close the loop: auditing isn’t a dead report; it’s fuel for the next step.

Key concepts:

Feedback · rewrites status · feeds the next.

What is:

A real run, condensed: from the start ("never miss a deadline again") to audit, with handles “Couple A/B”.

Why learn:

Ties the whole track to a single case — you watch the OS take shape and get scored.

Key concepts:

End-to-end example · handles · real scorecard.
