📦 What is an AI Operating System

Command center for a domain: the concept, the origin, the examples, and the anti-pattern “install instead of cultivate.”

What is:

An AIOS is a command center for a specific domain of your life or business—not a single tool.

Why learn:

It's the foundation of everything: without defining the concept, you'll confuse an OS with "just another app."

Key concepts:

Domain · command center · tailored to each area of life.

What is:

The concept was born from workshops where the author sought the visual analogy that clears up confusion about AIOS.

Why learn:

Understanding its origins shows that it’s more art than science—and that a simple mental model is enough.

Key concepts:

Simple mental model · visual analogy · art > science.

What is:

Five real OSs: Freedom (residencies/passports), Tax (laws/auditing), Skool (ads), Health, Marketing.

Why learn:

The examples make “one OS per domain” concrete and give you a reference for your own.

Key concepts:

One OS per domain · each with a different composition.

What is:

In practice, an OS is a handful of folders + an identity file (CLAUDE.md).

Why learn:

Demystifies it: you don't need heavy infrastructure to get started, just a file structure.

Key concepts:

Folders · master file · plumbing > model.

What is:

The concept works with any harness: Claude Code, Codex, open code. The folder changes, not the idea.

Why learn:

You aren’t tied to one tool; your investment survives changes.

Key concepts:

Tool-agnostic · portable · same idea, different folders.

What is:

There's no fixed formula: each OS is designed by feel, then adjusted through use.

Why learn:

Frees you from the search for the “perfect setup” — what matters is iterating.

Key concepts:

Design > engineering · iteration · judgment.

What is:

Treating the OS as a product ready to install is the mistake. It's a garden you cultivate.

Why learn:

Set expectations: 80% in a weekend, solid only with daily use and auditing.

Key concepts:

Cultivate > install · living system · trial by fire.

🍕 The 6 layers and the pie chart

Why the pie isn’t split evenly, the order that works, and the #1 mistake: jumping to agents too soon.

What is:

Identity, Substrate/Context, Rules & Hooks, Skills, Tools, Agents.

Why learn:

It’s the structural vocabulary of every OS — a reference for the technical learning paths.

Key concepts:

6 layers · foundation vs. action.

What is:

Slices vary by domain: in a Tax OS, context weighs ~34%; in others, skills or tools dominate.

Why learn:

You stop treating all layers as equal and invest where it hurts most.

Key concepts:

Distribution by domain · unequal percentages.

What is:

The build sequence: Identity → Substrate → Rules → Skills → Tools → Agents.

Why learn:

Building out of order wastes effort; the foundation supports capability.

Key concepts:

Order of operations · foundation before capability.

What is:

Most people start with agents—the last layer—before they have a foundation.

Why learn:

Avoids the most common and costly mistake beginners make.

Key concepts:

Agents last · prerequisites first.

What is:

Static layers (Identity, Substrate, Rules) support the dynamic ones (Skills, Tools, Agents).

Why learn:

Organizes the course: Track 2 = foundation, Track 3 = action.

Key concepts:

Static = back of house · dynamic = front.

What is:

Preview of how Tax, Sales, Support, Content, and Consulting redistribute the layers.

Why learn:

Previews Track 5 and practices asking “which layer matters here?”

Key concepts:

Tax ~34% context · Sales ~30% · preview.

What is:

In a new domain, it’s sometimes worth gathering context before writing the identity.

Why learn:

The order is a guide, not dogma: you adjust it based on what you know (or don't know).

Key concepts:

Naive in the domain · context-first.

📖 Essential Glossary

Foundation: define each term inline. Identity, substrate, rule vs. hook, skill, agent, CLI/MCP/API, nugget, context rot, reverse meta-prompting, raw vs. synthesized.

What is:

The soul of the OS: who it is, whom it serves, what it refuses. It lives in the CLAUDE.md.

Why learn:

It’s the first file the OS reads — it sets the tone for everything.

Key concepts:

Soul file · concise · < 30 lines.

What is:

Substrate = stored reference material; context = what goes into the conversation when needed.

Why learn:

Distinguishing the two prevents bloating the context window.

Key concepts:

Reference · injected on demand.

What is:

Rule = “do not enter” sign (strong suggestion); hook = locked door (deterministic).

Why learn:

You decide what can be "flexible" and what must be unbreakable (PII, money).

Key concepts:

Nondeterministic vs. deterministic.

What is:

A skill is a recipe card: a packaged task that runs the same way every time.

Why learn:

It's the unit of capability — starts manual, then becomes a recipe.

Key concepts:

Verb · repeatable · 1 task.

What is:

The chef who chooses the tool and tastes the dish: orchestrates several skills with judgment.

Why learn:

Separate the "verb" (skill) from the "worker" (agent)—only promote routines you already do by hand.

Key concepts:

Judgment · orchestrates skills · review gate.

What is:

CLI = a lean remote control; MCP = a power adapter; API = a data port; skill = a recipe.

Why learn:

Knowing how to choose avoids unnecessary infrastructure (all infrastructure becomes maintenance).

Key concepts:

4 connectors · MCP loses relevance · read-only CLI.

What is:

Nugget = super-distilled summary; context rot = context that grows stale; reverse meta-prompting = asking AI to distill the conversation into a skill.

Why learn:

These are the concepts most people ignore — and what separates a living OS from a dead one.

Key concepts:

Distill · decay · recipe after cooking.

What is:

Folder raw/ (raw, kept as a backup) versus a distilled folder (nuggets that go into the context).

Why learn:

It’s the data pattern that repeats in every domain: pantry vs. finished dish.

Key concepts:

raw > synthesized · inject only nuggets.
