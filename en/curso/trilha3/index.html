🛠️ Skills — the Verbs You’ve Earned

The OS’s unit of capability. Start by hand, distill with reverse meta-prompting, iterate forever—and know when a skill should become a script.

What is:

Do the task manually first — sometimes spending an hour typing out all your reasoning — and only then capture the steps in a skill.

Why learn:

A skill for something you’ve never done by hand comes out generic and breaks. Doing it manually first ensures the recipe reflects reality.

Key concepts:

Manual first · context priming · capture the process.

What is:

Ask the AI: "based on this conversation, distill the exact criteria and turn them into a slash command I can always reference".

Why learn:

It’s writing down the recipe after cooking: never redo the same one-hour briefing again.

Key concepts:

Distill the conversation · slash command · recipe after the meal.

What is:

You release a V1 and keep refining it. The author has a skill that’s been fine-tuned almost every day for six months.

Why learn:

Treating a skill as "ready" lets it decay. The cycle is alive: use, observe, adjust.

Key concepts:

Ship a V1 · continuous iteration · ∞.

What is:

At the end of the session, you ask "how should we adjust the skill?" and provide a rubric for when to change something (or not).

Why learn:

The rubric prevents impulsive adjustments: the skill changes only when the criteria justify it.

Key concepts:

Post-mortem · rubric · change with criteria.

What is:

If a skill runs 100% autonomously (fixed input→output), it may be better as a deterministic script/cron job written by the AI.

Why learn:

A script uses fewer tokens and less context, and doesn’t need to be loaded into the window every session.

Key concepts:

100% autonomous · cron · context savings.

What is:

People underuse it, accumulate it, or think they’re clever and create too many skills that go stale—and skills for things they’ve never done by hand.

Why learn:

Starting with ONE skill (the one you repeat most often) keeps your folder from filling up with dead recipes.

Key concepts:

One skill first · no hoarding · no ghost skills.

What is:

A ready-to-use prompt that asks Claude Code to distill the current conversation into a /slash command that accepts an argument.

Why learn:

It’s the practical exercise: you leave the module with your first skill brought to life.

Key concepts:

Copy-run · argument · SOP in sequence.

What is:

The parts of a SKILL.md: name, when to use it (trigger), the step-by-step procedure (SOP), and how to verify it.

Why learn:

Knowing the anatomy lets you read, debug, and improve any skill—yours or someone else’s.

Key concepts:

Name · trigger · SOP · done-check.

What is:

A good skill is validated. Skills on the same topic run only when called by name, unused ones go into reserve, and trio-skills installs by lightweight, medium, or heavyweight profile.

Why learn:

Keeps the OS lean, safe, and easy to grow.

Key concepts:

Validator · direct invocation · reserve · profiles.

🔌 Tools & Connections — the wires to the outside

Skill, CLI, API, or MCP alone? How to wrap an API in your own CLI — and the security hack that changes everything: a read-only CLI.

What is:

Before connecting any tool, audit it: does it offer a skill, CLI, API, or only MCP? The answer determines the path.

Why learn:

Choosing wrong costs maintenance and context. The question filters first, before you spend effort.

Key concepts:

Audit the tool · 4 connectors · make an informed choice.

What is:

Over time, MCP tends to become less relevant. It’s only worthwhile when the tool offers MCP but not an API.

Why learn:

You stop installing MCPs by reflex and prefer a skill or CLI when there’s an API.

Key concepts:

MCP in decline · MCP-only is the exception · prefer API.

What is:

You can ask Claude Code: "turn this API into a custom CLI with these main functions".

Why learn:

When the work involves a lot of command-line use, your own CLI is leaner than calling the raw API.

Key concepts:

API wrapper · selected functions · lean remote control.

What is:

Design the CLI so it physically has no write access—it only reads data, never writes to the database.

Why learn:

Eliminates the risk of a POST accidentally destroy data when you're deep into the context window.

Key concepts:

Read-only · no write access · physical tripwire.

What is:

Each connection or CLI you add is another piece to maintain. Add with intention, not by reflex.

Why learn:

Too much infrastructure breaks more than it helps. Sometimes a ready-made skill does the job without you building anything.

Key concepts:

Maintenance cost · intentionality · less is more.

What is:

Supabase CLI (Health OS database), Obsidian CLI (second brain), and the Appify skill (scraping) — ready to use, with no CLI of its own.

Why learn:

Show when to build your own infrastructure and when a third-party skill already does the job.

Key concepts:

CLI when needed · skill when enough · combine them.

What is:

A ready-to-use prompt that asks to turn an API into a CLI read-only, with the functions you list.

Why learn:

It’s the practical exercise: you leave with a safe CLI for your favorite tool.

Key concepts:

Copy-run · read-only · explicit functions.

What is:

If a ready-made skill (e.g., Appify) already does the job, don’t break your back maintaining your own CLI just out of pride.

Why learn:

Recognizing when to stop is just as valuable as knowing how to build. Every extra piece is debt.

Key concepts:

A ready-made skill is enough · don’t reinvent · infrastructure debt.

What is:

The runtime/ kit (rules, bridges, guard, and 7 recipes) assigns each action a level from N0 to N4, and a single file specifies which model each app uses.

Why learn:

Keeps the OS lean, safe, and easy to grow.

Key concepts:

MCP bridge · guard · level per action · single source of truth.

🤖 Agents — Roles with Judgment

The last layer, not the first. A skill is a verb; an agent is the chef who chooses skills, in order, with a review gate before anything goes out.

What is:

Skill = one repeatable verb. Agent = a specialist worker that orchestrates multiple skills with judgment.

Why learn:

Confusing the two leads you to create an agent when a skill would have been enough — expensive and fragile.

Key concepts:

Verb vs. worker · judgment · orchestrates skills.

What is:

Every agent that produces something going outside passes through a review gate: a point where you (or another agent) checks it before sending.

Why learn:

It’s what separates a reliable agent from one that sends nonsense to a client/accountant.

Key concepts:

Review gate · human in the loop · check before sending.

What is:

Only promote a routine to an agent if you already perform it manually today, with existing skills for it to orchestrate.

Why learn:

An agent without underlying skills or a real routine becomes theater: it looks powerful but doesn’t deliver.

Key concepts:

Real routine · skills first · prerequisite.

What is:

A one-off task (auditing 100s of files) might call for a dynamic workflow, not a fixed agent. Need more power? Spin up disposable sub-agents.

Why learn:

Not every task deserves a permanent "employee." Choosing the right form saves.

Key concepts:

Fixed agent · workflow · throwaway sub-agents.

What is:

In Freedom OS: a response agent (scans Gmail and drafts replies using the right documents) and a deep research agent (monitors changes to passport laws).

Why learn:

Real cases show agents as “employees” in a domain — each with a clear job.

Key concepts:

Response agent · deep research · living OS.

What is:

A skeptical reviewer agent (devil's advocate) that "chews you out before the accountant/client does": checks the work before it goes out.

Why learn:

Reduces back-and-forth: your own OS roasts you before the mistake reaches anyone who matters.

Key concepts:

Skeptical reviewer · devil’s advocate · adversarial gate.

What is:

As models get smarter, the same agent needs less instruction — or the agent is no longer needed because the harness already does it natively.

Why learn:

Makes you revisit agents periodically instead of accumulating them forever.

Key concepts:

Less instruction · the agent disappears · periodic review.

What is:

A copyable skeleton of AGENT.md: role, the skills it orchestrates, order, review gate, and limits.

Why learn:

It’s the practical exercise: you leave with your first agent sketched out and ready to fill in.

Key concepts:

Copy-run · role + skills + gate · limits.

What is:

Recipe R2 (team of 3 roles), model and effort per task, Agent Council, and cross-review between Claude ↔ Codex until approved.

Why learn:

Keeps the OS lean, safe, and easy to grow.

Key concepts:

R2 · right model · Council · cross-review.
